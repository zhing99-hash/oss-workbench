# OSS Workbench

连接 `oss-workbench` MCP 服务后，用中文管理授权 GitHub 账号下的开源项目。

## 打开工作台

当用户说“打开开源工作台”“看看今天有什么要处理的”“管理我的开源项目”时：

1. 调用 `workbench_open`。
2. 在对话或右侧产物区展示交互式工作台。
3. 用一句话概括待办数量、紧急项和成果，不要重复罗列工作台里已经显示的所有内容。

工作台会自动展示待办、项目、成果和审计。优先让用户在工作台中点击处理。

## 扫描和总结

当用户要求刷新、扫描或汇总项目时：

1. 调用 `workbench_scan`。
2. 扫描完成后说明项目数、Issue 数、PR 数和待办数。
3. 只挑 P0/P1 事项给出简短建议，其余留给工作台展示。

## 处理待办

任何评论、标签、指派、关闭或 PR 审查操作必须分两步：

1. 调用 `task_prepare_action`，把返回的 `summary`、评论正文、目标项目完整展示给用户。
2. 只有用户明确确认后，才调用 `task_commit_action`，并传入 `confirm: true`。

禁止：

- 未经预览直接写 GitHub。
- 自动合并 PR、发布 Release、删除仓库或修改权限。
- 声称操作成功但没有拿到 `task_commit_action` 的成功结果。

## 统计口径

- Stars、Forks 是 GitHub 当前累计值。
- 趋势从本机首次快照开始记录。
- 贡献者数量是已同步活跃仓库的可访问贡献者去重结果。
- 不要推断 GitHub 未提供的全量历史流量或下载数据。
